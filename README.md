Server REST API Endpoints (DiagnosticController)All endpoints require a valid Firebase ID token in the Authorization: Bearer <idToken> header (verified automatically by your existing FirebaseAuthenticationFilter).MethodEndpointDescriptionPOST/api/diagnostics/uploadValidates and saves a single diagnostic snapshot to MySQL (diagnostic_records), compares it against the user's previous record, and returns HTTP 201 Created with DiagnosticUploadResponse.POST/api/diagnostics/upload-batchValidates and saves a list of diagnostic snapshots (useful for syncing offline cached JSON snapshots) and returns HTTP 201 Created.GET/api/diagnostics/latestReturns the user's most recent diagnostic snapshot along with its HistoricalComparisonDto (or HTTP 204 No Content if none exist).GET/api/diagnostics/history?limit=20Returns up to limit (1–100) historical diagnostic records ordered from newest to oldest.3. How to Trigger Diagnostic Upload from the Client (pc-doqtar)Inside your client lifecycle or diagnostic completion handler (such as ApplicationLifecycle or DiagnosticsPage), call ServerHandover.uploadSnapshot(...):import org.pcdoqtar.connection.ServerHandover;
import org.pcdoqtar.connection.ServerHandover.UploadOutcome;
import org.pcdoqtar.diagnostics.SystemDiagnostics;
import org.pcdoqtar.model.SystemHealthSnapshot;

// 1. Collect hardware snapshot via OSHI
SystemDiagnostics diagnostics = new SystemDiagnostics();
SystemHealthSnapshot snapshot = diagnostics.collectSnapshot();

// 2. Upload snapshot using the authenticated Firebase ID token
ServerHandover handover = new ServerHandover();
UploadOutcome outcome = handover.uploadSnapshot(idToken, currentSessionId, snapshot);

if (outcome.success()) {
    System.out.println("Saved MySQL Record ID: " + outcome.recordId());
    System.out.println("Historical Comparison: " + outcome.trendAssessment());
} else {
    System.err.println("Upload failed: " + outcome.message());
}
4. Environment & Server URL ConfigurationServer (pc-doqtar-connection-service): Set DB_URL, DB_USERNAME, and DB_PASSWORD in your environment variables. Because spring.jpa.hibernate.ddl-auto=update is enabled in application.properties, Hibernate will automatically create the diagnostic_records table and its indexes on startup.Client (pc-doqtar): By default, ServerConnection connects to https://pc-doqtar-connection-service.vercel.app. When testing against a local Spring Boot server on http://localhost:8080, set the environment variable PC_DOQTAR_SERVER_URL=http://localhost:8080 or pass -Dpcdoqtar.server.url=http://localhost:8080 in your JVM arguments.
